# 텍사스 홀덤 2주차 진행 폴더

37팀 · 송준석 / 표신현

여러 명이 접속하여 채팅하고, 방장이 게임 시작을 누르면 각자 개인 카드 2장을 받는 버전입니다.
서버와 클라이언트는 **서로 다른 Java 프로세스**로 실행합니다.
소스는 하나의 Eclipse 프로젝트의 src에 모았습니다. package 선언 없이 기본 패키지를 사용합니다.

## 현재 구현된 범위

- 최대 6명 접속, 고유 ID와 닉네임 등록, 중복 닉네임 거절
- 전체 참가자와 가상 칩 1000개 표시
- UTF-8 한글 채팅과 접속·퇴장 안내
- 최초 참가자를 방장으로 지정, 방장 퇴장 시 다음 참가자로 자동 변경
- 2명 이상일 때 방장만 게임 시작 가능
- 서버에서 52장을 섞어 각자에게 중복 없이 개인 카드 2장 배분
- 개인 카드는 본인에게만 전달, 공개 참가자 정보에는 카드 내용 미포함
- 창 닫기와 나가기 버튼으로 연결 종료, 서버는 계속 접속 대기

**이번 버전은 개인 카드 배분까지입니다.** 공용 카드 5칸은 빈칸이며,
차례·베팅·공용 카드 공개·족보·승패·칩 정산은 아직 구현하지 않았습니다.
칩은 1000개로 표시되며 변하지 않습니다.

2주차의 카드 배분 확인을 위해 방장은 '다시 배분'을 누를 수 있습니다.
새 참가자가 들어오거나 누군가 나가면 모든 손패를 지우고 대기 상태로 돌아갑니다.
완성된 홀덤의 중도 입장·퇴장 규칙은 이후 게임 진행 기능과 함께 구체화합니다.

## Windows에서 실행

1. ZIP 전체를 새 폴더에 압축 해제합니다. Java 17 이상이 필요합니다.
2. run-server.bat를 실행합니다. 서버는 콘솔에 접속 대기 상태를 표시합니다.
3. run-client.bat를 **두 번** 실행합니다. 각각 게임 창이 열립니다.
4. 같은 PC에서는 서버 127.0.0.1, 포트 5555를 유지합니다.
5. 두 창에서 서로 다른 닉네임을 입력하고 접속합니다.
6. 참가자 목록과 채팅을 확인한 뒤 방장 창의 게임 시작을 누릅니다.
7. 두 창에 서로 다른 개인 카드 2장이 표시되는지 확인합니다.

클라이언트는 게임 창 안에서 입력합니다. 추가 입력 팝업과 별도의 클라이언트 콘솔은 없습니다.
서버의 검은 창은 서버 실행 상태를 보기 위한 창입니다.
게임 창이 열리지 않으면 명령 프롬프트에서 다음 명령으로 오류를 확인할 수 있습니다.

```bat
java -version
java -jar dist\week2-client.jar
```

수정한 소스로 배치 실행 파일을 갱신하려면 JDK 17 이상에서 build.bat를 실행합니다.
Eclipse에서 소스를 수정한 것만으로 dist의 JAR가 자동 변경되지는 않습니다.

## Eclipse에서 실행

1. File > Import > General > Existing Projects into Workspace
2. 압축을 푼 TexasHoldem_Week2 폴더를 선택하고 프로젝트를 가져옵니다.
3. JDK 17 이상을 프로젝트 JRE로 설정합니다.
4. src의 ServerMain.java를 우클릭하여 Run As > Java Application으로 실행합니다.
5. ClientMain.java를 같은 방법으로 **두 번** 실행합니다.
6. 나타난 두 게임 창에서 다른 닉네임으로 접속합니다.

서버 Console의 글자가 깨지면 서버의 Run Configurations > Common > Encoding을 UTF-8로 설정합니다.
게임 창의 입력은 Swing에서 처리하고 소켓 입출력은 UTF-8로 고정했습니다.
서버/클라이언트를 종료할 때는 자신의 게임 창이나 해당 Java 실행만 종료하세요.

## 파일과 담당

| 파일 | 담당 | 역할 |
|---|---|---|
| src/ServerMain.java | 송준석 | 접속별 Thread, 닉네임 등록 연결, 채팅 전달, 메시지 처리 |
| src/ClientMain.java | 송준석 | 서버 접속, 수신 Thread, 순서대로 송신, 프로토콜 해석 |
| src/Card.java | 표신현 | 카드의 무늬·숫자와 전송 형식 |
| src/Deck.java | 표신현 | 52장 구성, 섞기, 순서대로 꺼내기 |
| src/GameTable.java | 표신현 | 참가자 상태, 방장, 카드 배분 |
| src/GameView.java | 표신현 | 기본 게임 화면과 버튼·채팅 입력 |
| docs/protocol.md | 공동 | 메시지 형식과 각 방향의 처리 규칙 |
| reports/ | 개인별 | 2주차 보고서 두 개 |

게임 로직은 서버에서 실행하고 게임 화면은 클라이언트에 둡니다.
누가 파일을 담당하는지와 프로그램이 어디에서 실행되는지는 별개입니다.

읽는 순서는 Card → Deck → GameTable → ServerMain → GameView → ClientMain을 권장합니다.
게임 로직만 볼 때에는 앞의 세 파일부터 읽으면 됩니다.
별도 Java 라이브러리를 추가하지 않고 JDK의 Socket, Thread, Swing, 컬렉션을 사용했습니다.

## 통신 방식

명령어와 데이터는 UTF-8 한 줄로 전송합니다. 전체 규약은 docs/protocol.md에 있습니다.
채팅은 서버가 전달한 내용을 한 번만 표시합니다. [송신]·[수신] 중복 표시와 WELCOME/ACK/BYE는 없습니다.
JOIN_OK는 참가자 ID를 전달하는 실제 참가 승인 메시지입니다.
종료는 나가기 또는 창 닫기로 소켓을 닫으며, 채팅의 QUIT 문자열은 일반 대화로 처리합니다.

다른 PC에서 접속할 때에는 같은 네트워크에 연결한 뒤 서버 PC의 IPv4 주소를 입력합니다.
서버 PC에서 Java의 통신 허용과 TCP 5555 접근이 필요합니다.
우선 같은 PC에서 두 클라이언트를 실행해 동작을 확인하세요.

## 검증 자료

evidence/network_results.json과 로그는 작성 지원 환경에서 실제 Java 서버에 TCP로 접속한 결과입니다.
중복 닉네임, 정원, 한글 채팅, 시작 권한, 개인 카드 전달, 재배분, 퇴장 후 접속을 확인했습니다.
docs의 화면 이미지는 실제 ClientMain 두 개를 서버에 연결한 후 Swing 패널을 렌더링한 것입니다.
검증 환경은 Linux OpenJDK 21이며 Java 17 대상 형식으로 빌드했습니다.
Windows 배치 파일의 실제 실행과 Eclipse UI는 이 환경에서 직접 검증하지 않았습니다.

Python 3이 있는 경우 아래 검사를 다시 실행할 수 있습니다. 게임 실행에는 Python이 필요하지 않습니다.

```text
python tests/run_checks.py
```
